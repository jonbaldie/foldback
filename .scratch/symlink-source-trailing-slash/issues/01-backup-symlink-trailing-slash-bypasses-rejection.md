# `backup` with trailing slash on symlink source root bypasses symlink rejection and traverses target

Found by runtime-instrumented and action-sequence testing, 2026-09-11 (foldback 0.1.0.0, commit 53e78c7, macOS/APFS, normal build).
Evidence: `/tmp/foldback-finding-bugs-20260911/` (report: `report.md`, replay logs `repro-symlink-{1,2,3}.txt`, script `repro-symlink-trailing-slash.sh`).

## User impact

Foldback documents and tests that backup roots must be real directories, not symbolic links (`README.md`: "restores snapshots without following source symlinks"; `test/Main.hs:146-154`: `testRejectsSymlinkSourceRoot`).

However, if a user invokes `backup` with a trailing slash on the source path — the universal default behavior of shell tab-completion in zsh and bash when completing a directory symlink (`foldback backup my-link/<TAB>`) — the symlink rejection is completely bypassed:
- `backup` exits 0 and records the snapshot root as `Directory "."`.
- Rather than preserving or refusing the symlink, `scanTree` follows the symlink and recursively backs up the contents of the target directory.
- Restoring the snapshot reconstructs a concrete directory tree instead of a symlink, silently altering filesystem semantics.
- If the symlink points to a large, external, or sensitive directory tree, Foldback traverses and archives it against the documented filesystem semantics.

In contrast, invoking `backup` without the trailing slash correctly refuses with `user error (source is not a directory: ...)`.


## Expected vs actual

- **Expected**: `backup` refuses symlink source roots regardless of whether a trailing path separator is present (e.g. `source is not a directory: ...`).
- **Actual**: `backup` with a trailing slash succeeds (exit 0), dereferences the symlink, and dumps the target directory's contents into the snapshot.

## Grounding

In `src/Foldback/Repository.hs:90-93`:

```haskell
backup :: FilePath -> Maybe String -> FilePath -> IO BackupReceipt
backup repository requestedName source = do
  sourceExists <- doesDirectoryExist source
  unless sourceExists (ioError (userError ("source is not a directory: " <> source)))
  sourceStatus <- Posix.getSymbolicLinkStatus source
  when (Posix.isSymbolicLink sourceStatus) (ioError (userError ("source is not a directory: " <> source)))
```

Because `doesDirectoryExist` follows symlinks, the author explicitly added `Posix.getSymbolicLinkStatus source` to detect and reject symlink roots.

However, under POSIX `lstat` semantics, a trailing slash on a path forces resolution of the final symlink component. When `source` is `"source-link/"`, `Posix.getSymbolicLinkStatus "source-link/"` queries the target directory rather than the symlink itself, resulting in `Posix.isSymbolicLink sourceStatus == False`.

## Fix direction

Normalize or drop trailing path separators on `source` before inspecting symbolic link status:
- In `src/Foldback/Repository.hs:backup`:
  ```haskell
  let cleanSource = dropTrailingPathSeparator source
  sourceStatus <- Posix.getSymbolicLinkStatus cleanSource
  ```
  or `normalise source`.
- Update `testRejectsSymlinkSourceRoot` in `test/Main.hs` to verify that both `sourceLink` and `sourceLink <> "/"` are rejected.

### Agent Brief

**Category:** bug
**Summary:** Reject symlink source roots with a trailing path separator, so the symlink check can't be bypassed by slash-suffixed paths

**Current behavior:**
`backup` rejects a source root that is a symbolic link by lstat-ing it. Under POSIX lstat semantics a trailing separator forces resolution of the final component, so `backup <link>/` — the form shell tab-completion produces for a directory symlink — passes the symlink check and the directory check, and the snapshot silently archives the link target's contents as concrete files, contradicting the documented no-symlink-following semantics.

**Desired behavior:**
`backup` refuses a symlink source root regardless of trailing path separator(s), with the existing `source is not a directory` message and non-zero exit. A real directory with a trailing separator (e.g. `<dir>/`) continues to be accepted. Interior symlinks are unchanged — the documented behavior of never following source symlinks during traversal is unaffected.

**Key interfaces:**
- The source validation at the top of the backup operation in the repository module (currently: directory-existence check, then an lstat symlink check): normalize the source path (drop trailing separators / normalise) before both checks, so the lstat sees the final component as given by the user's intent rather than the slash-resolved node.
- The existing test covering rejection of a symlink source root: extend to cover the trailing-separator form.

**Acceptance criteria:**
- [ ] `backup <symlink> --repo ...` is refused (unchanged)
- [ ] `backup <symlink>/ --repo ...` is refused with the same message class, non-zero exit, and no snapshot created
- [ ] `backup <real-dir>/ --repo ...` still succeeds and archives the directory
- [ ] The restored tree from a real directory backup is unchanged in behavior
- [ ] Existing tests pass; the symlink-rejection test now covers both forms

**Out of scope:**
- Adding symlink-following or dereference options for sources
- Changes to restore target handling or repository-disjointness checks
